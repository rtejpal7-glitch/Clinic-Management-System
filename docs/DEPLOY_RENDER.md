# Put ClinicFlow online (Render + Vercel)

Once this is set up, nothing runs on your laptop. Each `git push` to `main` redeploys the site.

| Part | Where it runs | Set up by |
|---|---|---|
| Website (React) | Vercel | `frontend/vercel.json` |
| API server (C++) + PostgreSQL | Render, Singapore region | `render.yaml` (a Render "Blueprint") |

This uses the **free** plans, which are for a demo with synthetic data only:
- The API sleeps after 15 minutes with no visitors. The first request afterwards takes about a minute.
- The free database **expires 30 days after it is created**. Upgrade it in Render before then if you want to keep the data.
- Don't enter real patient information. The demo accounts' passwords are published in this repository.

---

## Part 1 — Render: API and database (about 20 minutes, mostly waiting)

1. Go to **render.com** and sign up with your GitHub account.
2. In the Render Dashboard, click **New → Blueprint**.
3. Connect the **Clinic-Management-System** repository. Render finds `render.yaml` and lists two items: **clinicflow-db** (Postgres) and **clinicflow-api** (web service).
4. Render asks for **BOOTSTRAP_ADMIN_PASSWORD**. Type a password for the `admin` account:
   - 10 or more characters, with letters **and** digits;
   - must **not** contain the word "admin";
   - for example `Clinic-Online-2026`. Write it down.
5. Click **Deploy Blueprint** (or **Apply**). The database starts in a minute or two. The API builds the C++ server from source the first time, which takes about **10–20 minutes**.
6. Open **clinicflow-api** in the dashboard. When the status shows **Live**, copy its address at the top of the page, for example `https://clinicflow-api.onrender.com` (yours may have extra letters at the end).
7. Check it: open `https://<your-api-address>/api/v1/health` in the browser. You should see `"status":"ok","database":"up"`.

The encryption keys and the database password are generated by Render and kept in the service's **Environment** tab. Never regenerate `DATA_ENCRYPTION_KEY` or `BLIND_INDEX_KEY` after data exists.

## Part 2 — Vercel: point the website at the API (5 minutes)

1. In VS Code, open `frontend/vercel.json`. Find this line:
   ```json
   "destination": "https://clinicflow-api.example.invalid/api/:path*"
   ```
   Replace `https://clinicflow-api.example.invalid` with your API address from Part 1, step 6. Keep `/api/:path*` at the end:
   ```json
   "destination": "https://clinicflow-api.onrender.com/api/:path*"
   ```
2. Save, then in the VS Code terminal:
   ```powershell
   git add frontend/vercel.json
   git commit -m "Point Vercel at the Render API"
   git push
   ```
3. Vercel redeploys on its own. In the Vercel project, check **Settings → Build and Deployment → Root Directory** is `frontend`. The build should now finish.

## Part 3 — Load the demo data (once, from your laptop)

Wake the API first by opening the health address from Part 1, step 7. Then, in the VS Code terminal at the project folder (use `py` if `python` is not found):

```powershell
python scripts\seed_demo.py --api https://<your-api-address>/api/v1 --admin-pass <your admin password>
python scripts\seed_derm_demo.py --api https://<your-api-address>/api/v1 --admin-pass <your admin password> --approve-content-for-demo
```

Then open your Vercel address and sign in: `admin` with your password, or the demo accounts (`dr.kavya`, `reception`, … with `Clinic-Demo-2026`).

**On the iPad:** open the Vercel address in Safari, then **Share → Add to Home Screen**.

## If something goes wrong

| What you see | What to do |
|---|---|
| Vercel build: "vercel.json still sends /api to the placeholder" | Part 2 is not done yet, or the change was not pushed. |
| Sign-in fails right after the site was idle | The free API is waking up. Wait a minute and try again. |
| Render logs: `Password does not meet the policy` | In clinicflow-api → **Environment**, change `BOOTSTRAP_ADMIN_PASSWORD` (letters and digits, 10+ characters, without "admin"), then **Manual Deploy**. |
| Render logs: `Could not create the database role clinicflow_app` | See below. |
| Seed script: `Login failed for admin` | Use the password you typed in Part 1, step 4. |

### If the role cannot be created

Normally the API creates its own least-privilege database login (`clinicflow_app`) on first start. If the Render database login is not allowed to create logins, the API stops with the message above. For a demo, run with a single login instead:

1. Open **clinicflow-db** → **Connect** → copy the **Internal Database URL**.
2. Open **clinicflow-api** → **Environment** → add:
   - `DATABASE_URL` = the Internal Database URL
   - `ALLOW_SHARED_DB_ROLE` = `true`
3. Save the changes. Render redeploys the API.

Clinic isolation (row-level security) still applies in this mode, but the separate least-privilege grants do not. Use it for demos only.

## How it works

- `render.yaml` makes the database private (no internet access) and gives the API the owner login as `MIGRATION_DATABASE_URL`. On start, the API creates or updates `clinicflow_app` with the generated `APP_DB_PASSWORD`, applies the migrations, and serves requests as `clinicflow_app`. The API refuses to run as a superuser, as a login that bypasses row-level security, or as the schema owner (unless `ALLOW_SHARED_DB_ROLE=true`).
- Only changes under `backend/` or to `render.yaml` rebuild the API. Website-only pushes rebuild just Vercel.
- `APP_ENV` is `demo`: the admin keeps the password you typed. In `production` the admin must change it at first sign-in, and the seed scripts would need that change first.
- More on Vercel: `DEPLOY_VERCEL.md`.

This was tested against a local PostgreSQL 16 set up like a hosted database (an owner login with role-creation rights, and one without). It has not been run on Render itself.
